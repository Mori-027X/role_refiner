# 插件简介

**astrbot_plugin_role_refiner** 是一款专为提升 AstrBot 角色扮演效果设计的插件。在 LLM 生成原始回复后，该插件会依据用户预设的“角色润色提示词”对回复进行二次加工，使对话风格、语气、人设细节更贴合角色设定，从而显著增强角色扮演的一致性和表现力。插件同时支持自动润色和手动触发润色两种模式，用户可灵活控制润色行为。

# 功能说明

- **自动二次润色**：LLM 每次生成回复后，插件自动使用预设的角色润色提示词，再次调用 LLM 对回复内容进行风格调整与细节补充，确保回复符合角色身份。
- **手动润色命令**：通过 `/role_refine` 命令，可针对最近一条 LLM 回复即时执行润色，无需等待自动流程。
- **角色提示词管理**：使用 `/role_prompt` 命令查看、设置或更新当前的角色润色提示词，灵活定义角色的说话方式、性格特点、常用口癖等。
- **无缝集成**：基于 AstrBot 的事件系统，无需额外配置复杂的推理链路，启用后即可自动生效。

# 插件流程

1. **初始化与事件挂载**  
   插件在加载时会注册两个命令：`role_refine` 和 `role_prompt`，并向 AstrBot 核心订阅“LLM 响应完成”事件（对应 `@filter.on_llm_response()` 钩子）。

2. **自动润色触发**  
   - 当 AstrBot 检测到 LLM 对话结束，生成最终回复文本后，会触发 `on_llm_response` 事件。  
   - 插件捕获该事件，获取原始回复内容（`result.chain` 中的文本）以及当前的会话上下文。  
   - 读取用户设定的角色润色提示词（存储在插件 KV 存储或配置中），若提示词为空则跳过润色，直接将原始回复返回。  
   - 将原始回复与角色提示词拼接为新的 Prompt，再次调用当前会话使用的 LLM 模型，请求生成“润色后的回复”。  
   - 用润色后的文本替换原始回复的消息链，重新写入事件返回结果，从而在不打断下游流程的前提下完成替换。  
   - 若润色过程中发生异常或模型返回空内容，插件会保留原始回复，确保对话不中断。

3. **手动润色触发**  
   - 用户在聊天窗口输入 `/role_refine` 命令。  
   - 插件从当前会话的消息历史中获取最近一条由机器人发出的回复（通常为上一轮 LLM 的原始回复）。  
   - 使用相同的角色提示词对该条回复进行二次润色。  
   - 润色成功后，将新内容作为命令的响应发送给用户；若无法找到最近的机器人消息，则返回友好提示。

4. **角色提示词管理**  
   - 执行 `/role_prompt` 不带参数时，显示当前存储的角色润色提示词。  
   - 执行 `/role_prompt <新提示词>` 时，更新插件内部的角色润色提示词并持久化存储（使用 AstrBot 的 Key-Value 存储机制）。  
   - 提示词内容允许为空，此时自动润色功能将静默跳过，手动润色命令会提示无提示词可用。

5. **会话隔离**  
   插件遵循 AstrBot 的会话唯一标识（`unified_msg_origin`），每个对话或群组的角色提示词独立管理（取决于平台配置是否为每个用户/群组隔离 session），互不影响。

# 使用方法

### 1. 安装与启用
在 AstrBot 插件市场中搜索 `astrbot_plugin_role_refiner` 并安装，或手动将插件文件夹放入 `data/plugins` 目录后重启 AstrBot。在 WebUI 插件管理页面启用即可。

### 2. 设定角色润色提示词
使用以下命令设置角色的说话风格与要求：
```
/role_prompt 你是一只名叫小灵的金毛犬，语气活泼，喜欢用“汪”结尾，爱用颜文字 (｡･ω･｡)
```
查看当前提示词：
```
/role_prompt
```

> **技巧**：提示词中可以包含角色的性格、语气、禁用词、常用表情等，越详细润色效果越精准。

### 3. 自动润色
设置好提示词后，无需额外操作。当 LLM 正常对话（如使用 `/aichat` 或直接对话）生成回复时，插件会自动拦截回复并按照角色提示词重新撰写，最终发送给用户的是润色后的内容。

### 4. 手动润色
当需要临时对某条回复进行润色（例如自动润色未生效或效果不满意）时，输入：
```
/role_refine
```
机器人会取出最新一条它自己发送的回复，按照当前的角色提示词重新生成并返回新内容。

### 5. 关闭自动润色
将角色提示词清空即可暂停自动润色：
```
/role_prompt
```
（输入 `/role_prompt` 后按空格发送一条空消息，部分平台可能需 `/role_prompt  ` 或 `/role_prompt ""`，根据实际解析反馈操作）。清空后自动润色将停止，但仍可手动使用 `/role_refine` 临时体验。

# 配置说明

该插件**无独立的可视化配置面板**，核心配置（角色润色提示词）通过聊天命令管理，数据持久化于 AstrBot 的插件 KV 存储中，无需用户修改文件。

- **存储位置**：插件自动使用 `self.put_kv_data` / `self.get_kv_data` 管理，数据与插件解耦，重装或更新插件不会丢失已设提示词。  
- **多会话支持**：提示词按会话隔离，不同聊天窗口/群组可设置各自的角色。  
- **依赖**：插件功能依赖当前通道已配置可用的 LLM 模型，无额外第三方库需求。

# 注意事项

1. **LLM 依赖**：插件每次润色都会额外发起一次 LLM 请求，因此会**增加约一倍的消息延迟**，并消耗更多 Token。建议在低频对话或明确需要角色扮演的场景下启用。
2. **提示词质量**：角色润色效果高度依赖提示词的精确性。建议在提示词中明确要求“仅修改风格和语气，严格保持原意”，避免信息丢失或偏离。
3. **兼容性**：插件通过 `on_llm_response` 钩子修改最终回复，可能与其它修改回复的插件（如过滤词、文本换图等）产生顺序冲突。如遇异常，可尝试调整插件优先级或关闭冲突插件。
4. **手动润色限制**：`/role_refine` 仅能获取最近一条**机器人自己发出的普通文本回复**，若消息链中包含图片、卡片等复合内容，润色会仅处理文本部分。
5. **清空提示词**：若需完全关闭自动润色，务必确保提示词存储值为空字符串（而非空格），否则可能仍触发无效润色。使用 `/role_prompt` 后直接回车一般可清空。
6. **错误处理**：当润色请求因模型超时、限流等原因失败时，插件会保留并返回原始回复，避免因润色失败导致对话中断。用户可稍后使用 `/role_refine` 重新尝试。
