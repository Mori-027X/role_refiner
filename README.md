LLM 扮演角色时总会漏出助手味：一口气排三个反问，开口「确实」，收尾「有什么需要可以告诉我」。

这个插件在回复真正发出前拦一道，**只挑出这类句子**做二次改写，让角色语气更像真人聊天。

## ✨ 特性

| | 特性 | 说明 |
| :--: | --- | --- |
| 🎯 | **按需改写** | 先用检测层判断值不值得改，命中才发起 LLM 调用，不为一句正常回复白烧 Token |
| 🪶 | **越改越短** | 校验层强制结果只能变短、不能变长，杜绝「润色完反而更啰嗦」 |
| 🔀 | **双来源提示词** | 优先用手动设置的 `/role_prompt`，没设置就回退到当前会话的 `system_prompt`，开箱即用 |
| 🧠 | **可指定润色模型** | 能单独指定一个 Provider 来润色，避免模型改自己的输出、越改越助手腔 |
| 🛡️ | **多重兜底** | 超时、报错、空返回、校验不通过，一律保留原文，绝不吞消息 |
| 🔒 | **会话隔离** | 每个会话的提示词独立存储，多角色、多群互不干扰 |
| ♻️ | **防递归** | 内部改写调用会被标记跳过，不会自己套自己 |

## 🔍 工作流程

```text
   用户消息 ──► LLM 生成回复
                     │
                     │  on_llm_response 钩子拦截
                     ▼
        ┌────────────────────────────┐
        │  ① 检测层：要不要改？        │
        └─────────────┬──────────────┘
                      │
        ┌─────────────┴──────────────┐
        │ 命中硬信号，或软信号 ≥ 3 分   │ 都没命中
        ▼                            ▼
  ┌────────────────────┐     ┌──────────────┐
  │ ② 改写层：LLM 二次加工 │     │ 原样放行      │
  └─────────┬──────────┘     └──────────────┘
            ▼
  ┌────────────────────┐
  │ ③ 校验层：合格吗？    │
  └─────────┬──────────┘
            │
    ┌───────┴────────┐
    │ 通过            │ 不合格 / 超时 / 报错
    ▼                ▼
 替换原始回复      保留原文
```

### ① 检测层

只负责判断「要不要润色」，一个字都不改。命中任意一条即触发。

| 类型 | 信号 | 阈值 |
| :--: | --- | --- |
| 硬 | 复读用户 | 与用户消息的最长连续重叠 ≥ 5 字；或 ≥ 3 字且占回复比例 > 40% |
| 硬 | 多问号 | 问号（`？` / `?`）数量 > 1 |
| 硬 | 多句 | 句末标点（`。` `！` `？` `!` `?`）数量 > 2 |
| 硬 | 超长 | 去除首尾空白后 > 60 字 |
| 软 | 助手腔词密度 | 命中 3 次以上 **+2** 分，命中 2 次 **+1** 分 |
| 软 | 总结腔开头 | 以「总的来说 / 所以 / 因此 / 综上 / 首先 / 其次 / 听起来」开头 **+2** 分 |
| 软 | 客服腔结尾 | 含「有什么需要 / 可以告诉我 / 希望能帮到 / 建议你 / 你可以考虑」**+2** 分 |

> 软信号累计 **≥ 3 分** 才触发，避免误伤。

检测用的助手腔词表：

`确实` `听起来` `总的来说` `所以呢` `因此` `建议你` `你可以考虑` `有什么需要` `希望能帮到` `作为` `根据你的` `考虑到` `需要注意的是` `首先` `其次` `总而言之` `综上所述`

### ② 改写层

带着角色设定和几个示例让模型重写，默认模板的取向是「真人微信聊天语气，最多一句，15 字以内」。

- 调用超时上限 **15 秒**，超时直接放弃润色
- 模板占位符会先替换正文、后替换角色设定，避免角色设定里恰好含有占位符导致二次替换

### ③ 校验层

改写结果必须**全部通过**才被采用，否则原样放行：

- [x] 长度 ≥ 2 字
- [x] 原文超过 15 字时，结果不得 ≥ 原文长度的 95%（只能变短）
- [x] 不得含助手腔词
- [x] 不得与用户消息连续重叠 ≥ 5 字
- [x] 不得含换行（有换行说明输出格式没控住）

另外，模型爱加的 ```` ``` ```` 代码块、包裹引号、`改写后：` 这类前缀都会被自动剥掉。

## 📦 安装

**方式一：插件市场**

在 AstrBot WebUI 的「插件市场」搜索 `role_refiner` 直接安装。

**方式二：手动安装**

```bash
cd AstrBot/data/plugins
git clone https://github.com/Mori-027X/role_refiner.git astrbot_plugin_role_refiner
```

然后重启 AstrBot，或在 WebUI 插件页点「重载」。

> 需要 AstrBot **≥ 4.9.2**。

## 🎮 命令

| 命令 | 说明 |
| --- | --- |
| `/role_prompt` | 查看当前提示词来源（手动提示词 + 自动捕获的 system_prompt 预览） |
| `/role_prompt <提示词>` | 设置本会话的手动提示词，优先级高于自动捕获 |
| `/role_prompt clear` | 清空手动提示词，回退到自动捕获的 `system_prompt` |
| `/role_refine` | 对最近一条机器人回复手动润色一次，结果直接发出来 |

命令作用范围是**当前会话**，不同会话互不影响。

## ⚙️ 配置项

插件提供可视化配置面板，支持以下参数：

| 配置项 | 类型 | 默认值 | 说明 |
| --- | :--: | :--: | --- |
| `enable_auto_refinement` | 布尔 | `true` | 是否启用自动润色。关闭后自动润色停止，手动命令仍可用 |
| `auto_capture_system_prompt` | 布尔 | `true` | 是否自动捕获会话的 `system_prompt` 作为后备提示词 |
| `refine_provider_id` | 字符串 | 空 | 润色时使用的 Provider ID，留空则复用当前对话模型 |
| `refine_temperature` | 浮点 | `0.5` | 润色温度，取值 0–2，建议 `0.3 ~ 0.7` |
| `refine_max_tokens` | 整数 | `200` | 润色输出上限，建议 `100 ~ 300` |
| `refine_system_prompt_template` | 文本 | 见下 | 润色时使用的系统提示词模板 |

### 模板占位符

| 占位符 | 内容 |
| --- | --- |
| `{role_prompt}` | 角色设定（手动设置的优先，否则用捕获的 `system_prompt`） |
| `{user_message}` | 用户最近一条消息 |
| `{original_reply}` | 机器人原始回复 |

## ⚠️ 注意事项

1. **额外 LLM 调用** —— 每次触发改写都会多一次请求。插件已用检测层尽量少触发，但角色扮演场景密集时仍会明显增加 Token 消耗。
2. **建议换个模型润色** —— 让生成模型改自己的输出，容易越改越助手腔。推荐在 `refine_provider_id` 里指定一个风格更口语的 Provider。
3. **与分段回复插件不冲突** —— 本插件在 `on_llm_response` 阶段修改文本，和其他在 `on_decorating_result` 阶段工作的插件（如智能分段回复）顺序兼容。
4. **静默跳过的情况** —— 手动提示词和自动捕获的 `system_prompt` 都为空时，插件不报错、不做任何处理。
5. **缓存上限** —— 每个会话缓存的回复/提示词/用户消息各保留最近 200 条，重启 AstrBot 后清空。

## ❓ 常见问题

**Q：启用了但感觉没反应？**

A：大概率是没命中检测条件。已经很短、很自然的回复本来就不会被改，这是刻意设计的。

**Q：会不会改得面目全非，甚至丢消息？**

A：不会。校验层卡了长度、助手腔、复读、换行四道关，任何一道不过就退回原文；请求超时或报错同样保留原文。

**Q：`/role_refine` 提示「没有找到最近的机器人回复」？**

A：缓存是会话级的，且重启后清空。先让机器人在这个会话里发一条消息再试。

**Q：能同时给不同群配不同角色吗？**

A：可以。提示词按会话隔离存储，每个群、每个私聊都是独立的一份。
